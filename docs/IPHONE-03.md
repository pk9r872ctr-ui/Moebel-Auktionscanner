# Weiterarbeit ausschließlich mit dem iPhone

1. In Safari den Pull Request auf GitHub öffnen. „Files changed“, [Bericht](REPORT-03.md), [Quellenbelege](SOURCE-REGISTER-03.md) und „Checks“ prüfen. Nicht automatisch mergen.
2. Rechtmäßig nutzbare echte Angebotsdatei beschaffen und in iOS **Dateien** ablegen. Fehlende Rechte nicht durch manuellen Import umgehen. Anbieter werden durch den Scanner nicht kontaktiert. Mindestens 20 Angebote für die erste fachliche Abnahme.
3. Standardformat: [CSV-Vorlage](../examples/import-template.csv) oder JSON nach [Importvertrag](IMPORT.md). Rechercheformat: Pflichtspalten und Preisarten aus [Rechercheanleitung](RESEARCH-IMPORT-03.md). Numbers-Export muss zu UTF-8/Semikolon und Spaltenvertrag passen; fremde CSV nicht ungeprüft umbenennen. Datum mit Zeitzone, EUR, originale IDs und Rechtebeleg nötig. Unbekannte Zahlen nicht schätzen, um Sperren zu entfernen.
4. Zur Weiterentwicklung Codex den berechtigten Datensatz separat bereitstellen. Keine echten Geschäftsdaten, SQLite-Dateien oder Secrets in GitHub committen. Änderungen/Tests können über Codex und GitHub überprüft werden; das iPhone braucht keine Python-Installation.
5. **Noch kein App-Link und keine installierte PWA.** Privaten HTTPS-Betrieb erst separat freigeben. Kostenlosen Einstieg, persistenten Speicher, Zugriffsschutz und Worker-Laufzeit zuvor konkret prüfen. Kein kostenpflichtiges Konto aktivieren. Ein schlafender Gratisdienst bietet keinen kontinuierlichen Scan.
6. Sobald später ein geprüfter privater Host vorhanden ist: anmelden → Nutzerimport → Vertrag wählen → Rechte prüfen → Datei aus „Dateien“ hochladen. Originaldaten und Sperren ansehen. Bei konfigurierter privater Datenbank ist dauerhaftes Speichern eine separate Schaltfläche; sonst bleibt Upload sitzungsgebunden.
7. Such-/Filterbereich nutzen; Loskosten im Export ergänzen, Vollkostenplan einschließlich ausdrücklich bestätigter Nullkosten und Steuerbelege ausfüllen. Merkliste/Kandidaten markieren bedeutet manuelle Auswahl, keine nachgewiesene Profitabilität. Aktualisierte Angebote erneut prüfen. Scannerstatus zeigt abgeschlossene Dateiläufe, nicht verifizierte Live-Quellen.
8. JSON-Exporte nur privat speichern. Kandidatenexport ist für die spätere abgestimmte ERP-Übergabe; er wird nicht automatisch versendet. Vollkostenplan-Eingaben bleiben derzeit in der Sitzung.
9. Nach späterer Manifest-/HTTPS-Abnahme Safari → Teilen → „Zum Home-Bildschirm“. [Apple-Anleitung](https://support.apple.com/en-eg/guide/iphone/iphea86e5236/ios). Installierbarkeit, OIDC und Synchronisation auf einem echten iPhone noch testen. Home-Bildschirmstart erzeugt keinen Offline-/Hintergrundscan.
